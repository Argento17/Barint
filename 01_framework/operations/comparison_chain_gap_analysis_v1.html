3 · Efficiency — Same Quality, Less Time & Cost

EFF-1 · Shift truth checks left — the 6-run lesson

Yogurt's cost structure: errors injected at B/C, discovered at F → B-to-F reruns. Every plausibility assertion moved from F to C converts a multi-session regen into a minutes-level parse fix. The same checks, earlier, are ~10× cheaper.

EFF-2 · Commit the drafted CI — it's written and has never run DATAFRONTEND

.github/workflows/barint_ci.yml already defines the right gates (next build · lint · corpus validation · BSIP0 nutrition tests · 64 enricher tests · router + golden-corpus regressions · BSIP0 gate tests) — but the folder is untracked; no PR has ever been CI-checked. One commit makes the frozen-invariant and build gates automatic.

Add one missing job: the OFF-string sweep (openfoodfacts|off_api over bari-web/src/data/) — today that Phase-J check is manual.

EFF-3 · Finish the shared packaging core — TASK-233F, 10 generators pending DATA

Each category has a bespoke builder (build_yogurts_frontend_v4.py, _v006.py…) — every honesty gate and format change re-implemented per category. That is exactly how single-category safeguards happen. One core = write once, all categories inherit.

EFF-4 · Reconcile the factory skill with practice

The skill mandates per-stage artifacts; only 4 categories have them (cereals, cheese_spreads, juices, hard_cheeses) — yogurt, the newest and most scrutinized run, produced none. Either the shared runner emits them automatically (preferred; free once EFF-3 lands) or the skill trims to artifacts that earn their keep. A spec the flagship run ignores trains agents to ignore the spec.

EFF-5 · Unblock the close gate — cheap-LLM verification lane CC

Mechanical claim-verification (file exists, counts match, grep clean, build green) is zero-judgment work → Stupid-LLM lane with idiot-proofed prompts; CC reviews the evidence table. Target: RETURNED→CLOSED in hours, not days.

EFF-6 · Parallelize copy (G) and packaging (H) after score freeze

They share one dependency: frozen scores + traces. After QA freeze, dispatch Content and Data in parallel; H consumes G's strings at the end. ≈ one session saved per category.

EFF-7 · Name the Shufersal-VPN dependency as an operational gate

Yogurt re-acquisition waited on Israeli-IP VPN availability — an undocumented bottleneck for every future scrape. Cheap fix: a scrape-window runbook (when VPN is up, which scrapes queue, who flips it) so Phase B never silently stalls.

4 · Additions — What Doesn't Exist Yet

ADD-1 · Post-deploy production smoke test (automated) — must-have

The prod/local split survived for months because nothing watched the live site. TASK-245 fixed the topology; CC verified the flip manually — but no recurring check exists. Minimum: a scheduled job hitting every /hashvaot/* route asserting HTTP 200, 0 OFF refs, expected data-version marker. The regression alarm for the whole "what's actually live?" failure class.

ADD-2 · Live-state manifest: route → data version → run ID → baseline — must-have

Gap 2 of the prod-sync brief was exactly this absence — enumerating the re-point payload required hand-diffing repos. A small machine-readable manifest, written by packaging and asserted by the smoke test, makes "what is live?" a lookup instead of an investigation.

ADD-3 · BSIP0 scrape QA standard as a blocking gate — must-have

TASK-218's deliverable, closed and wired into Phase B for every future scrape (institutional form of FIX-2). The weakest link in the chain is between retailer HTML and BSIP1 — it deserves a standing gate, not per-category heroics.

ADD-4 · Data-freshness policy per category — must-have

No policy says when a category must re-verify (reformulations, recalls, price moves). Even coarse — "re-scrape + re-verify every N months; show the date; stale categories get a banner" — converts an unbounded liability into a scheduled cost.
