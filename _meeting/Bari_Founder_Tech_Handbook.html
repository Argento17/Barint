1Five mental models

Get these five and you can reason about almost any technical question, even ones you've never heard.

Figure A — The single most important picture: two halves joined only by JSON files. Memorise this and most questions answer themselves.
1 · Backend vs. Frontend
The backend is everything the user never sees — the data collection, the scoring, the logic. The frontend is what they do see — the website on their phone.
Analogy
A restaurant: the kitchen (backend) cooks; the dining room (frontend) serves. Diners only see the plate.
In Bari
Backend = the Python pipeline that scores 500 products. Frontend = the Next.js website. They never mix.
2 · Deterministic vs. Probabilistic
Deterministic = same input always gives the exact same output. Probabilistic = the output can vary, like an AI that answers slightly differently each time.
Analogy
A calculator is deterministic (2+2 is always 4). Asking a person “rate this 1–10” is probabilistic (you'll get 7, then 6).
In Bari
The scoring engine is deterministic — this is your single biggest credibility claim. A score reproduces exactly, every time.
Say it
“Deterministic means same product in, same score out — every time. No AI mood swings.”
3 · Traceable vs. Black box
Traceable = you can see exactly why it produced an answer. A black box gives an answer with no explanation.
In Bari
Every score writes a “trace” — a record of which rules fired. It's deterministic and traceable; the two are different properties (reproducible vs. explainable) and we have both because it's rule-based code, not a model.
Say it
“Deterministic is about reproducibility; traceable is about explainability. We have both — because it's code, not a guess.”
4 · Rule-based vs. Machine Learning (ML)
Rule-based = a human wrote explicit logic (“if sugar > X, then…”). ML = a model learned patterns from data and you can't fully see its reasoning.
Analogy
Rule-based is a recipe you can read line by line. ML is a chef who “just knows” — great food, but can't always explain the dish.
In Bari
The scoring is rule-based on purpose. That choice is what buys you both determinism and traceability at once.
5 · Pipeline
A series of stages where each one's output is the next one's input — like an assembly line for data.
Analogy
A factory line: raw material → cut → assemble → paint → box. Each station does one job and passes it on.
In Bari
Scrape → Extract → Understand → Score → Build → Website. Each stage hands a file to the next.

2Data & how it's stored↑ top

How information is shaped and saved so software can use it.

Figure B — The anatomy of a JSON file. It's just labelled boxes of data. This is exactly what one Bari product looks like.
JSON “JAY-son”
The universal text format for storing and passing structured data. It's just labels and values wrapped in brackets (see Figure B). Every system can read it.
Analogy
A filled-in form: each field has a label (“Name:”) and a value (“Cottage 5%”).
In Bari
Every product, every score, every page is a JSON file. It's the seam — the one format where the backend hands data to the website.
Say it
“Each product is a JSON record — that's the single interface between our engine and our site.”
Key / Value · Field
A key is the label ("score"); its value is the data (72). One key+value is a field. It's how all structured data is organised.
NULL “null”
A deliberate marker meaning “there is no value here.” Different from zero — zero is a number; null means unknown / not captured.
In Bari
Core to your integrity story: if a value wasn't scraped, the field is null and the page says “data could not be retrieved.” You never replace null with a guess.
Say it
“Missing data stays null — we'd rather show a gap than invent a number.”
Schema
The agreed shape of your data — which fields exist and what type each is. A contract that keeps every record consistent.
Analogy
A blank form template: everyone fills in the same fields in the same order.
Database vs. Files (and SQLite)
A database is specialised software for storing/querying lots of data (e.g. PostgreSQL, MySQL). File-based means storing data as plain files instead. SQLite is a tiny database that lives in a single file.
In Bari
Bari is mostly file-based (JSON) on purpose — so every result is reproducible and trackable in version control. A small SQLite file just records run lineage (which scrape produced which score).
Say it
“We chose a versioned file pipeline over a database — auditability matters more to us than query speed at this stage.”

3The backend — making the data↑ top

The tools that gather and judge the product data.

Python
A popular, readable programming language — the standard choice for data, science and automation work.
In Bari
The entire backend — scrapers, the Hebrew parser, the scoring engine — is Python. Chosen because the data and scientific tooling live there.
Web scraping
Automatically collecting data from websites by programmatically loading their pages and reading the content.
In Bari
How product data enters the system — scraping up to four Israeli retail chains directly. (No crowd databases, ever.)
Headless browser · Playwright
A headless browser is a real web browser running with no window, controlled by code. Playwright is the popular tool for driving one.
Analogy
A robot that opens the retailer's website exactly like a shopper would — but reads and saves the page automatically.
In Bari
Our scrapers use Playwright so we see what a real customer sees, including pages that only load with a full browser.
OCR “optical character recognition” · Azure
OCR turns a photo of text into actual text a computer can read. Azure is Microsoft's cloud, where we run that OCR.
In Bari
For reading nutrition values off photographs of physical product labels when they aren't on the website.
Parsing · Enrichment
Parsing = reading messy raw text and pulling out the meaningful parts. Enrichment = adding derived insight on top (e.g. “this flour is whole-grain”).
In Bari
The “Understand” stage: a Hebrew ingredient parser detects flour type, additives, fermentation and protein source, then enriches the record before scoring.
Script · Batch job
A script is a small program that does one task. A batch job runs a task over many items at once.
In Bari
Each category is scored by a batch run — one command processes the whole shelf and writes every product's result.

4Testing & trust↑ top

How engineers make sure a change doesn't silently break something — your strongest “we're serious” signals.

Unit test · pytest
A unit test is a small automated check that one piece of code does what it should. pytest is the standard tool for running them in Python.
In Bari
The Hebrew label-reader alone has 64 automated checks. If a change breaks one, you know instantly.
Regression test · Baseline · Diff
A regression is when a new change accidentally breaks old behaviour. A baseline is a saved “known-good” result. A diff shows exactly what changed between two versions.
Analogy
Re-photographing every product after a change and laying it next to the old photo to spot anything that moved.
In Bari
Change a rule → re-run all ~500 products → diff every score against the committed baseline. If something moved that shouldn't have, the gate fails. No eyeballing.
Say it
“Every rule change re-runs all 500 products and diffs against a baseline before it's allowed to count.”
Version control · Git · Commit
Git records every change to the code/data over time, so you can see history and undo anything. A commit is one saved snapshot.
Analogy
Track Changes for an entire project — every edit, who made it, and a button to roll back.
In Bari
Because the data is files, every score is in version control — you can prove how any number came to be, historically.
Reproducibility
The property that anyone, anytime, can re-run the process and get the identical result. The gold standard for anything making a claim.
Say it
“Reproducibility is the whole game for a system that makes health-adjacent claims — and ours has it by design.”

5The frontend — the website↑ top

The technology that turns your JSON into the page a shopper sees.

Figure C — How a web page loads: the browser sends a request; the server sends back a response it then renders.
Next.js “next J-S”
A leading framework for building fast, modern websites. It's the structure the whole Bari site is built on.
Analogy
A pre-built chassis for a car — you don't forge the frame from scratch; you build on a proven one.
In Bari
The site is Next.js. It reads the finished JSON and displays it — it never recalculates a score.
React · Component
React is the most popular tool for building interactive interfaces. A component is a reusable building block (a button, a card, a comparison row).
Analogy
LEGO bricks — build one “product card” once, reuse it for every product.
In Bari
Every page is assembled from a small set of shared components — which is why all pages look consistent.
TypeScript
JavaScript (the language of the web) plus type safety — it catches whole classes of mistakes before the code ever runs.
Analogy
A form that rejects letters in a phone-number box — it stops bad data before it causes a problem.
In Bari
The website is TypeScript, so the shape of every JSON field is checked — the site can't accidentally misread a score.
Tailwind (CSS)
CSS is what styles a web page (colours, spacing, fonts). Tailwind is a popular, consistent way of writing it.
In Bari
Keeps the visual design uniform across every page, via shared design tokens.
RTL “right-to-left”
Layout for languages that read right-to-left, like Hebrew and Arabic. Harder than it sounds — everything mirrors.
In Bari
The whole site is built RTL-correct for Hebrew — a real piece of engineering and part of your local moat.
Rendering · DOM · Responsive
Rendering = turning code/data into the visible page. The DOM is the page's live structure in the browser. Responsive = the layout adapts to any screen size.
In Bari
Pages are mobile-first and responsive — the target is a shopper understanding the shelf in 15–20 seconds on a phone.
Server-side / Static rendering (SSR / SSG)
Two ways to build a page: SSR builds it fresh on the server per visit; SSG builds it once ahead of time so it loads instantly. Most sites mix both.
In Bari
Comparison pages can be pre-built from the JSON, so they're fast and cheap to serve.
Deploy · Vercel
Deploying = publishing the website so the public can reach it. Vercel is the hosting service built for Next.js sites.
In Bari
“Re-publishing” a category = regenerate its JSON, then redeploy the site. No hand-editing of live pages.
Accessibility · WCAG · Contrast
Making a site usable by everyone, including low-vision users. WCAG is the standard; contrast is whether text is readable against its background.
In Bari
A design reviewer checks every page for contrast and accessibility before it ships.

6AI & language models↑ top

Where AI sits in Bari — and, just as importantly, where it does not.

The line that wins the room: AI in Bari does two narrow jobs — helping read messy Hebrew labels, and helping draft consumer copy. It never sets a nutrition value or a score. The verdict is deterministic code. That's what separates you from an “AI nutrition app.”
LLM “large language model” · Model
An AI trained on huge amounts of text that can read and write language (ChatGPT, Claude, etc.). A model is the trained system itself.
In Bari
Used for language tasks (parsing help, copywriting) — outside the scoring path, always checked downstream.
Prompt
The instruction you give an AI model to get an output.
Analogy
The brief you hand a freelancer — the clearer the brief, the better the result.
Hallucination
When an AI confidently states something false. The core reason you can't let an LLM produce nutrition facts or scores.
Say it
“We never let a model invent a number — that's exactly where AI hallucinates. Numbers come from the scrape and deterministic code.”
Agent · Orchestration
An agent is an AI given a job and some tools to do it. Orchestration is coordinating several agents/roles toward one outcome.
In Bari
Production runs as a coordinated set of specialist roles (data, research, content, QA) with one lead checking each result against evidence before it counts.
Training vs. Inference
Training = teaching a model from data (slow, expensive, one-time). Inference = using the finished model to get an answer (fast).
In Bari
Useful to know if the engineer asks. Today Bari doesn't train its own model; the future “personalisation engine” is where ML/training could enter — and even then, it sits beside the deterministic score, not inside it.

7Engineering glue & practices↑ top

The connective concepts that come up in any technical conversation.

API “application programming interface”
A defined way for two systems to talk to each other — one program asks, another answers, in an agreed format.
Analogy
A restaurant menu: a fixed list of things you can order and what you'll get back. You don't go into the kitchen.
In Bari
Relevant to the plan: selling the scored data to a health fund could mean exposing it through an API their app calls.
Repository (“repo”) · Monorepo
A repo is the project's folder of code, tracked by Git. A monorepo keeps several related projects in one repo.
In Bari
Bari is a monorepo: the data/scoring workspace and the website live together but stay cleanly separated.
Feature flag · Rollback
A feature flag is an on/off switch for a change, so you can release it safely or turn it off instantly. A rollback undoes a change.
In Bari
New scoring rules ship behind a flag (default off) with a defined rollback — so nothing changes published scores by accident.
Say it
“Every scoring change is behind a flag with a rollback — we never let an experiment touch live scores silently.”
Gate · Conformance check
A gate is an automated checkpoint that blocks a change unless it passes. A conformance check verifies something still follows the required structure.
In Bari
Before a category goes live it must pass gates (data integrity, no regressions, the red-team review). A conformance check confirms every category will still re-flow when the engine changes.
Edge case
An unusual input that breaks normal assumptions — the thing that exposes weak software.
In Bari
e.g. a product with a missing panel, or a whole-food fat like almonds that's calorie-dense but healthy. The engine has deliberate handling (floors) for these.

8Bari's own vocabulary↑ top

Internal terms — mainly for your understanding. Most of these stay in-house; don't lead with them to outsiders.

Trace
The full record a score writes — every rule that fired, every cap, every dimension's contribution. The source of “traceability.”
Dimension
One of the ten angles the engine scores a product on (processing, nutrient density, etc.), each 0–100.
Cap · Floor
A cap is a hard ceiling on the score (serious problems can't be outweighed). A floor is a protective minimum (whole foods aren't punished for natural traits). These do the heavy lifting at the extremes — more than the weights.
Score · Grade
The score is the 0–100 number; the grade (S–E) is the band it falls into. The grade is for the shopper; the score drives the ranking.
BSIP internal — keep in-house
Your internal name for the pipeline's three stages (extraction → enrichment → scoring). Useful shorthand internally; to outsiders just say “our pipeline.”

10Sound fluent · avoid these slips↑ top

Three sentences that signal you know your architecture:
“It's deterministic — same input, same score, with a full trace.” “The engine and the site meet only through generated JSON.” “Every rule change is regression-gated against all 500 products.”
Don't say / watch for:
  • Don't call the scoring “AI” or “the algorithm learns” — it's rule-based and doesn't learn. Saying otherwise undercuts your whole credibility story.
  • Don't collapse “deterministic” and “traceable” into one word — they're two different claims (reproducible vs. explainable). You have both; say both.
  • Don't overclaim productionization. The honest line: “the engine and pipeline run end-to-end and are proven; hardening it into a clean service is exactly what a technical partner would own.”
  • Don't guess a number you don't know. “I'd have to check the exact figure” beats a confident wrong answer — every engineer respects that more.
