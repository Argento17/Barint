# Forensic Traceability Report — Live Published Scores (2026-06-26)

Commissioned by owner: "scoring of products you can't trace their origins — who produced it and when — and cut the tools that produced this." Two independent lanes (per-product census + git forensics/tool inventory) + an orchestrator dependency-safety check.

## Headline
- **570 live BSIP-scored products across 15 served files.**
- **175 (31%) UNTRACEABLE** — cannot be regenerated at all.
- The untraceability tracks **one cause**: a family of **one-off, task-tagged scripts that bypassed the canonical pipeline**. Every category scored through the canonical pipeline is clean; every untraceable category was scored by an ad-hoc script.

## Critical caveat on "WHO" (honest limit)
Git attributes **every** commit in this repo to a single human identity (`Tom Bar Haim <tbarhaim@gmail.com>`) — the one identity all lanes (Sonnet/Cursor/Grok/Gemini/orchestrator) commit under. **Git cannot tell us which AI lane authored a given file.** So "who" can only be answered as **which TOOL produced it**, not which model. All dates/commits below are git-verified; lane attribution is not recoverable from git.

## Root cause — the tools that did this (the bypass family)
A cluster of ad-hoc scripts that **hard-code flags in-script, mint private run-ids, apply custom scope filters, and write frontend JSON directly** — bypassing the canonical path (`configs/*.json → rescore_all.py → generate_page.py`). Several were never committed. They do not record a reproducible provenance block.

The **canonical spine** (`spine_flip.py → rescore_all.py → generate_page.py`, all tracked, built 2026-06-17/18) records full provenance and is the drop-in replacement for every cut item.

## Cutting alone does NOT regenerate the lost scores
Two more steps are required after the cut:
1. **Re-onboard the 3 untraceable categories through the canonical spine** (create their `configs/*.json` + ensure the source corpus exists), so cookies_coffee / protein_bars / granola become reproducible. Chocolate needs its corpus committed first.
2. **Spine fix:** add `_meta.run_id` + full flag-vector emission to `generate_page.py` so canonical files stop showing a blank run_id (closes the cosmetic "partial" gap for bread/cheese).

## Recommended guardrail (prevent recurrence)
A C0 gate: refuse to publish/serve any frontend score JSON that lacks a full provenance block (config_sha256 OR run_id + complete flag vector + generator_version), and a check that the backing run dir is committed. Off-spine scores can never reach the site again.

## Execution note
Recommend cutting by **quarantine, not delete** (move to `03_operations/_quarantine_offspine_scorers/`): reversible for the tracked scripts (recoverable from git) and preserves the UNTRACKED ones (which would otherwise be unrecoverable). Requires the shared tree be clear of other active sessions at execution time.
